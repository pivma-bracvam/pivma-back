Roteiro em Duas Fases — Prévia (Spec 017)

Sessão: Não autenticado

Esta demonstração não representa nenhuma regra de negócio real de Planejamento. A "Fase 2" abaixo existe apenas para provar, com a API real, que o motor de processos e o frontend conseguem avançar o roteiro para uma atividade que não é formulário (activity_type, Spec 017) — sem nenhum endpoint novo.

1. Roteiro declarado (GET /processes/templates/validated_method_dossier)

Estrutura completa do método, incluindo a Fase 2, mesmo antes de qualquer instância existir.

2. Iniciar submissão de exemplo (POST /processes)

Processo: Nenhum

3. Preencher e enviar a submissão (Fase 1)

Reaproveita o formulário já existente de validated_method_dossier (Spec 011/013).

4. Aprovar a triagem (login como Avaliador)

Ao aprovar, a dependência da Fase 2 é satisfeita e planning_preview deve sair de bloqueada.

Este método tem avaliação por IA configurada em ambientes que já rodaram o seed completo (seed_all). O processo entrou em AI_PRE_EVALUATION; aguardando a IA liberar a triagem (a Fase 1 continua igual à Spec 013 — nada desta demo altera esse fluxo).

5. Roteiro da instância (GET /processes/{id} + GET /tasks)

Inspetor de Resposta da API

Nenhuma requisição realizada.
